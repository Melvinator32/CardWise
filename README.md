# CardWise

A single-file credit card and spend dashboard: categorizes transactions, tracks
points earn rates and card-level value, monitors statement credits against their
targets, and flags spend that went on a lower-earning card than it could have.
No build step and no dependencies.

## Run it
Open `index.html` in any browser, or serve the folder:

    python3 -m http.server 8000

then visit http://localhost:8000

## Demo data

**Every transaction in this app is fabricated.** The 1,900 transactions, their
merchants, amounts, dates and the statement-credit history are all generated by
`tools/make-demo-data.mjs` from a fixed seed. No real account, statement, or
spending history is included, and the portfolio timeline (which cards are held,
when they were opened) is invented too.

Card names, annual fees, earn multipliers and credit structures are real
published product terms, kept so the dashboard demonstrates something meaningful.

To regenerate the dataset:

    node tools/make-demo-data.mjs

It rewrites the `BAKED` object inside `index.html` in place. The seed is fixed,
so the output is identical every run unless you change it.

## Deployment

### Portfolio
Pushing to `main` rebuilds the demo at
https://jamesmcknight.me/demos/rewards-ledger/ — see
`.github/workflows/notify-portfolio.yml`.

### Cloudflare
The demo is also deployed to Cloudflare Workers static assets at
https://cardwise.jrmcknight08.workers.dev — see `wrangler.jsonc`.

Cloudflare Workers Builds is connected to this repo: every push builds, and
pushes to `main` deploy to production. `dist/` is gitignored; the `build`
command in `wrangler.jsonc` recreates it on every `wrangler deploy`, so the
dashboard needs no build command. To deploy by hand, run `npx wrangler deploy`
from a checkout with `wrangler` authenticated (`npx wrangler login`).

### Password

The Cloudflare deployment is password-protected server-side: `src/worker.js`
runs before every request and requires HTTP Basic credentials (any username)
whose password matches the `APP_PASSWORD` secret. Set or change it with

    npx wrangler secret put APP_PASSWORD

Set it under the Worker's Settings → Variables and Secrets, not as a Workers
Builds build variable, which the Worker never sees. `keep_vars` in
`wrangler.jsonc` stops deploys from deleting it if it is saved as a plain
variable rather than a secret. With no
secret set, the Worker serves nothing (503). For `wrangler dev`, put
`APP_PASSWORD=...` in a `.dev.vars` file, which is gitignored.

`index.html` also has an in-page lock screen that checks a SHA-256 hash of the
password (`LOCK_HASH`). It applies everywhere the page is served, including the
portfolio demo, but it only deters casual visitors because the page source is
readable. To change the password there, replace `LOCK_HASH` with the hex
SHA-256 of the new one.

`dist/` exists only so `README.md`, `tools/` and `.github/` are never served;
the `build` command just copies the two files into it.
